## Release gates

### Current v0.9 issues

**BUG-09-01: inconsistent sleep-entry times after changing the selected screen.** X4 Pro folder image initially took a very long time, then loaded faster on a repeat. Elias also reported varying waits while switching screens after the TickTick selector check. Following a request to repeat sleep with TickTick unchanged, he reported approximately five seconds, still perceived as delayed; separate durations for both requested attempts were not provided. Rendering works; predictable sleep timing is still unverified. The sleep path performs synchronous plugin network work before rendering, and non-screen-ready images can require a first conversion. Neither cause is confirmed on the device. Track timing and a trace or isolated plugin test in `outputs/RESULT.md` at the workspace root. Any fix must preserve queued reading-progress events and the existing selected image after network failure. X3 behavior remains untested. Resolve within the current v0.9 testing scope before v1 acceptance; this is not deferred to v1.1.

**BUG-09-02: slight delay waking from sleep.** Reported on X4 Pro after the sleep-screen tests; no duration or cause established. Track separately from BUG-09-01. Elias subsequently confirmed the current book returned to the same page he had left open, so reading-position retention passed for that cycle. Wake duration and post-wake page-turn responsiveness remain unmeasured. Determine whether the delay is expected initialization or a regression before selecting a fix. No X3 result is implied.

**BUG-09-03: missing usable Word Bank save control on X4 Pro.** Dictionary lookup is user-confirmed. Source inspection found saving bound only to a held logical Confirm; the current X4 Pro mapping points to an absent physical Confirm, and touch long-press starts definition selection. No Save action is rendered. Add a discoverable touch save action in the current v0.9 correction, preserve dictionary navigation and recursive lookup, and verify a saved entry can be reopened. Do not count lookup success as save acceptance or send the user an unsupported hold-to-save gesture. X3 physical save behavior remains pending.

**BUG-09-04: the user confirms different per-book text settings now save on X4 Pro; broader persistence/recovery checks remain open.** Elias repeatedly observed changes propagating both ways between two books. That version stores size/spacing/publisher styling without the font family, and repeating **Book text profile** disables the active profile. The USB backup is now verified: global settings were Literata 12 pt and the sole four-byte profile stored 12 pt, spacing 2 and publisher styling on. That backup step changed no reader files. The source correction stores and restores family with size, preserves global defaults even when Save follows edits, and separates **Save text settings for this book** from **Use global text settings**. Version 1 profiles migrate using the known global family; missing historical font names cannot be reconstructed. A temporary font-load failure retains the book's selection for retry. Four independent reviews, 37 host checks and both model-specific firmware builds passed. Elias accepted the behavior and installation. The corrected X4 Pro application was written, fully read back, and observed booting into a book; the original recovery bank and boot metadata remained unchanged. The user subsequently reported "Different text confirmed saving now," accepting the core per-book save behavior on X4 Pro. Reset, font-loss, sleep/restart and reading-position edge cases remain unverified. A separate About check confirmed CrossLoop `0.9.0-rc.3`. Retain progress and existing profiles. Font-recovery checks and a separate X3 installation remain open.

The first candidates have separate firmware and SD packs for X3 (528 × 792 portrait, ESP32-C3) and X4 Pro (480 × 800 portrait, ESP32-S3). Confirm the current set on both physical readers before starting v1.1. Firmware defaults are account-neutral. Each enabled sync service needs a setup, connection status and disconnect flow using the service's supported login, OAuth or API token. Keep credentials out of firmware, fixtures, logs and exports. Released rc3 uses sample/offline snapshots; unreleased rc4 has the native token connection and still needs live-account acceptance.

For each live connection, show which account or service is connected, when it last synced, and whether the reader is displaying an offline copy. Provide a clear setup path from Settings. Use provider login for OAuth, and masked entry for a supported API token. Keep location, weather units, feed URLs, calendar choices and selected task lists configurable per reader. Verify first-time setup, failed authorization, expiry, reconnect, and disconnect with test accounts before enabling a connection by default.

## Current rc.4 additions

Editable metadata, genre filters, series organization and richer settings moved into v1 preparation with Elias's November 8 request. v1.1 starts after v1 hardware acceptance; do not silently defer these requested features.

Elias requested weather graphics and more pictures for the next update after seeing the Today card. Add weather illustrations to the Today experience and expand the selection of sleep-screen pictures for both panel sizes.

PF-10 accepted behavior: extend the existing **Restore Light on Wake** control with a time-limited choice. Proposed UI choices are **Always off**, **Restore previous state**, and **Restore within…**, with a configurable duration. Duration presets and the default remain implementation choices; five minutes is an example, not Elias's selected preference. If the light was on immediately before sleep and the wake occurs within the selected window (including the boundary), restore its brightness and warmth. After that window, leave the light off while retaining the brightness and warmth settings. If the light was off before sleep, it stays off even on an immediate wake. In the time-limited mode, a cold boot or missing/invalid elapsed-time evidence starts with the light off. Distinguish normal sleep/wake from the existing silent maintenance reboot behavior.

PF-10 implementation boundary: reuse the light HAL, existing settings screen and SD state. The numeric preference retains off/previous meanings and adds timed restore. The X4 Pro RTC supplies elapsed-time evidence across sleep; missing or invalid timestamps leave the light off in timed mode. There is no timer task or Wi-Fi dependency. State size, build footprint and hardware timing remain to be measured. The control is capability-gated; X3 has no frontlight setting. Host checks cover invalid values and existing restore behavior; physical sleep/wake checks remain required.

For each incoming feature, capture the requested outcome, device, priority, a concrete example, and what would count as working. Record which parts belong on the reader and which belong on BRUTUS. Include data access, power or storage implications, conflicts with existing behavior, and a way to undo the change. Keep source prototypes, local checks, and hardware acceptance distinct. Add new work here as Elias describes it.

PF-01 native design. A dedicated activity owns URL entry, links, history, and the saved-page picker. Reuse the existing URL keyboard, Wi-Fi picker, and plain-text reader. Both pinned board SDKs enable the ESP certificate bundle. Prototype a dedicated verified HTTPS transport with certificate and hostname checks, a deadline, and bounded redirects. Wait for a usable clock before certificate validation. Stream bounded text and links into the SD cache, preserve the saved copy after failure, and release Wi-Fi when the activity brought it up. The C3 panel is the lower-memory test target. This path uses no companion service.

PF-02 and PF-03 design. A single preference determines the active sleep provider and its selected asset. Both the TickTick app's **Use for sleep** action and the selector set that preference. Previewing is separate from applying. The demo uses sample tasks, a sample folder, and fixed daily entries. The sleep renderer should have one owner for the active source so existing root-image writers cannot overwrite the chosen screen.

PF-04 native design. Use the same verified HTTPS transport for a direct image URL. Stream to an SD temporary file and enforce byte and decoded dimension limits before conversion. The EPUB cover path already has JPEG and PNG converters with fit/crop support. Test their memory use and file replacement on the X3. Preview before selecting the result and retain the last usable image after an unsuccessful import.
